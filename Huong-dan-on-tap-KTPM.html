BẢN CHẤT ĐỒ ÁN KTPM & GIẢI THÍCH JUNIT 5 EXTENSION

Tài liệu tổng hợp ôn tập vấn đáp & báo cáo dành cho Yzy.

1. Bản chất Đồ án KTPM (Web UI Automation Testing)

  • Hệ thống kiểm thử (SUT): Website bán hàng mẫu SauceDemo (https://www.saucedemo.com).
  • Công nghệ: Java 17, Maven 3.9, Selenium WebDriver 4.27, JUnit 5 (Jupiter 5.11).
  • Mô hình kiến trúc Page Object Model (POM):
    • pages/: Quản lý locator và các thao tác click, gõ phím trên giao diện.
    • tests/: Kịch bản kiểm thử, kiểm tra kết quả kỳ vọng (Assertions).
  • Các kỹ thuật kiểm thử áp dụng:
    • EP (Phân vùng tương đương): Phân chia nhóm tài khoản hợp lệ, sai mật khẩu, tài khoản bị khóa trong LoginTest.
    • BVA (Giá trị biên): Kiểm tra giỏ hàng rỗng (N=0), thêm 1 món (N=1), thêm tối đa 6 món (N=6).
    • DT (Bảng quyết định): Kiểm tra các tổ hợp bỏ trống trường tại Step One form checkout (First Name, Last Name, Postal Code).
    • UC (Ca sử dụng): Kiểm thử luồng mua hàng xuyên suốt End-to-End và các nút hủy Cancel / Back Home.
    • DDT (Kiểm thử theo dữ liệu): Nạp dữ liệu từ file ngoài (login-data.csv, products.csv) dùng @ParameterizedTest và @CsvFileSource.
    • NFR (Phi chức năng): Đo thời gian phản hồi tải trang inventory ≤ 3 giây (PerformanceTest).

2. Giải thích chi tiết ScreenshotOnFailureExtension.java

Tại sao chọn AfterTestExecutionCallback thay vì TestWatcher?
Trong vòng đời JUnit 5, callback afterTestExecution() kích hoạt NGAY LẬP TỨC khi test method bị FAIL (ném ngoại lệ) và chạy TRƯỚC các hàm @AfterEach.
Lúc này trình duyệt vẫn còn đang mở nguyên trạng thái lỗi → Chụp ảnh thành công 100%.
Nếu dùng TestWatcher.testFailed(), callback này chạy sau @AfterEach (lúc đó driver.quit() đã đóng trình duyệt) → ném lỗi mất session NoSuchSessionException.

Chi tiết các dòng lệnh quan trọng:

  • Optional<Throwable> exception = context.getExecutionException();: Kiểm tra xem test case vừa chạy có ném ra lỗi hay không. Nếu có lỗi (test FAIL), exception.isPresent() trả về true.
  • if (testInstance instanceof WebTestBase webTestBase): Kiểm tra xem class test có kế thừa từ WebTestBase không, từ đó gọi webTestBase.getDriver() để lấy đối tượng điều khiển trình duyệt WebDriver.
  • File screenshot = takesScreenshot.getScreenshotAs(OutputType.FILE);: Ép kiểu sang TakesScreenshot để ra lệnh Selenium chụp lại toàn bộ màn hình và xuất ra file ảnh tạm thời.
  • Path outputFolder = Paths.get("evidence");: Định vị con trỏ đường dẫn tới thư mục evidence ở gốc dự án.
  • if (!Files.exists(outputFolder)) { Files.createDirectories(outputFolder); }: Dấu ! là phủ định. Ý nghĩa: "Nếu thư mục evidence CHƯA TỒN TẠI trên máy thì tự động tạo mới ra" (giúp code chạy trên bất kỳ máy nào cũng không sợ thiếu folder).
  • try { ... } catch (Exception e) { ... }: Bọc toàn bộ quá trình chụp và ghi file. Thao tác với trình duyệt và ghi ổ đĩa đều có rủi ro phát sinh ngoại lệ (đầy ổ đĩa, crash). Try-catch giúp bắt gọn mọi sự cố, chỉ in thông báo cảnh báo và tuyệt đối không làm sập (crash) chương trình kiểm thử JUnit.

3. Mã nguồn Extension: ScreenshotOnFailureExtension.java

package vn.edu.softwaretesting.core;

import java.io.File;
import java.nio.file.Files;
import java.nio.file.Path;
import java.nio.file.Paths;
import java.nio.file.StandardCopyOption;
import java.time.LocalDateTime;
import java.time.format.DateTimeFormatter;
import java.util.Optional;

import org.junit.jupiter.api.extension.AfterTestExecutionCallback;
import org.junit.jupiter.api.extension.ExtensionContext;
import org.openqa.selenium.OutputType;
import org.openqa.selenium.TakesScreenshot;
import org.openqa.selenium.WebDriver;

public class ScreenshotOnFailureExtension implements AfterTestExecutionCallback {

    private static final String EVIDENCE_DIR = "evidence";

    @Override
    public void afterTestExecution(ExtensionContext context) throws Exception {
        Optional<Throwable> exception = context.getExecutionException();
        if (exception.isPresent()) {
            captureScreenshot(context);
        }
    }

    private void captureScreenshot(ExtensionContext context) {
        Object testInstance = context.getRequiredTestInstance();

        WebDriver driver = null;
        if (testInstance instanceof WebTestBase webTestBase) {
            driver = webTestBase.getDriver();
        }

        if (driver == null) {
            System.err.println("[SCREENSHOT] Không tìm thấy WebDriver để chụp màn hình.");
            return;
        }

        try {
            if (driver instanceof TakesScreenshot takesScreenshot) {
                File screenshot = takesScreenshot.getScreenshotAs(OutputType.FILE);

                Path outputFolder = Paths.get(EVIDENCE_DIR);
                if (!Files.exists(outputFolder)) {
                    Files.createDirectories(outputFolder);
                }

                String className = context.getRequiredTestClass().getSimpleName();
                String methodName = context.getRequiredTestMethod().getName();
                String timestamp = LocalDateTime.now().format(DateTimeFormatter.ofPattern("yyyyMMdd_HHmmss"));

                String fileName = String.format("%s_%s_%s_FAIL.png", className, methodName, timestamp);
                Path destination = outputFolder.resolve(fileName);

                Files.copy(screenshot.toPath(), destination, StandardCopyOption.REPLACE_EXISTING);
                System.out.println("[SCREENSHOT] Đã lưu ảnh chụp lỗi: " + destination.toAbsolutePath());
            }
        } catch (Exception e) {
            System.err.println("[SCREENSHOT] Lỗi khi chụp ảnh màn hình: " + e.getMessage());
        }
    }
}

4. Tích hợp vào WebTestBase.java

@ExtendWith(ScreenshotOnFailureExtension.class)
public abstract class WebTestBase {
    protected WebDriver driver;
    protected String baseUrl;

    public WebDriver getDriver() {
        return driver;
    }
    // ... @BeforeEach và @AfterEach giữ nguyên
}

mvn clean test
